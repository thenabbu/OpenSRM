# W3.8 — goldens must not outlive their URL

## What the card asked for, and what was actually true

The card said `tests/golden/api/` is "the current-state golden set". **It is
not.** It is the pre-Vite baseline: `CHECK_DEFAULT` is `tests/golden/v3`, CI
checks `tests/golden/v3`, and `gates.sh` checks `tests/golden/v3`. The flat
`tests/golden/` tree is reachable only as capture mode's `--out` default, which
overwrites instead of checking. Nothing ever passed it to `--check`.

Measured, flat vs v3:

| | flat `tests/golden/` | `tests/golden/v3/` |
|---|---|---|
| `revision` in metrics.json | absent | `8de67ef` |
| `html_bytes` | 281,291 | 65,820 |
| `dom_nodes_page` | 2,271 | 310 |
| `api/static_dist_assets_app-HASH.*` | absent | present |
| `api/root.json` lists idiomorph | yes | no |

So idiomorph's golden was not "green and asserting nothing" — it was
**unchecked**, in an orphan tree. Different diagnosis, same rot.

## The second, real gap

`compare_tree` *does* catch a dead golden whose bytes still match: it reports
`only in golden: api/x.json`. But that is a drift message, and it only fires
when the gate is pointed at the tree holding the golden. There was no named
"this URL no longer exists" finding, and no check that a golden's recorded
`path` still resolves at all.

## Fix

1. Deleted the four dead current-state goldens, not just idiomorph — the same
   rule condemned all four, and fixing only the named one would have left
   siblings broken:
   `static_dash.js`, `static_pull.js`, `static_timetable.js`,
   `static_vendor_idiomorph.min.js`.
2. `dead_urls(golden, results)` — for every `api/*.json` under the checked dir,
   its recorded `path` must appear in the live capture. `--check` prints
   `DEAD GOLDEN URL: ...` and exits 1.
3. `capture_logout()` now returns its record and the caller folds it into
   `results`, so `/logout` is not read as a dead URL.

### Semantics that had to be right (learned by getting them wrong)

- **ALIVE is not 200.** `/logout` deliberately answers 302. Only 404/410 — the
  app saying the thing is gone — count as dead. First attempt used 2xx and
  reded a healthy v3 on inverting this rule.
- **`-HASH` is not a URL.** `api_name()` masks Vite build hashes at record
  time, so `app-HASH.css` can never be fetched back. Skipped.
- **Frozen baselines are supposed to name deleted files.** `v2/` is history.
  `--check` is only ever pointed at the current-state set.

## Break-proofs

| Proof | Result |
|---|---|
| `--selftest` (18 cases: 14 normalisation, 3 drift-gate, 1 dead-url incl. 302-alive + `-HASH`-skip + 404-dead + absent-dead) | exit 0 |
| Real gate on `tests/golden/v3` | `golden OK: 2f657d1 matches tests/golden/v3`, exit 0 |
| Planted golden for `/static/no-such-asset.js` | exit 1, `DEAD GOLDEN URL: 1 ...` names it |
| Pre-deletion flat tree as `--check` target | exit 1, names all 5 dead (4 assets + logout before the fold-in fix) |

## Untouched, proved by diff

`git diff --stat` touches only the script and the four deleted goldens.
`git status tests/golden/v2 tests/golden/v3` is empty. `v2/api/static_vendor_idiomorph.min.js.json`
still exists, unchanged — it is frozen history and is supposed to name the
deleted library.

## Known limit, deliberately not fixed here

`api/root.json`'s *body* still references `/static/vendor/idiomorph.min.js` in
the flat tree. `dead_urls` checks a golden's own `path`, not URLs mentioned
inside bodies — catching those means parsing every body for every URL, which is
a different (and much noisier) check. The orphan flat tree is carded separately.

## Related, not fixed here (as the card said)

W5.5's grep gate must scope around `tests/golden` rather than loosening its
pattern: the v2 baseline legitimately contains `idiomorph`.
