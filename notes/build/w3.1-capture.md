## 1. `--repo` (revision independence)

```
--repo    checkout/worktree to capture; precedence --repo > $OPENSRM_REPO > /opt/data/opensrm-repo
--python  interpreter that imports the app; <repo>/.venv/bin/python, then $OPENSRM_REPO/.venv/bin/python
```

`--repo` drives **everything**: the seed script runs with `cwd=<repo>`, gunicorn
runs with `cwd=<repo>`, the scope fixtures are read from `<repo>`, and the
resolved `git rev-parse --short HEAD` is printed and stored in
`metrics.json.revision`. A path without `app/app.py` is refused instead of being
captured silently (that silent wrong-revision capture was the bug).

Proof, tool run from the HEAD worktree, targets an older one:


## 2. The hydration race is gone

The wait is `settle(page, what)` → `page.wait_for_function(READY_JS)`, 30 s cap,
and on timeout it raises with the diagnostic dump (readyState, island count,
which islands are still unmarked) instead of continuing with a half-hydrated DOM.

The ready signal, in full:

```js
() => {
  if (document.readyState !== 'complete') return false;
  const isl = Array.from(document.querySelectorAll('[data-island]'));
  return isl.every(e => !!(e.dataset.hydrated || e.dataset.mountedAt));
}
```

* `data-hydrated` is stamped by each island's own hydrate function
  (`HYDRATED_ATTR` in `web/src/panels/*/[X]Panel.tsx`, `islands/sync-age.tsx`);
  `data-mounted-at` is the cache branch in `web/src/main.ts`. Only a mounted
  island can produce either, so this is app-produced completion, not a guess.
* A revision with **no** `[data-island]` at all (the pre-islands baseline,
  `1fcbfe6`) has an empty marker set, `.every` is vacuously true, and the
  predicate reduces to "document complete". One predicate, both revisions, no
  branching — that is what let W3.2 and W3.3 share this tool.

`networkidle` is gone from the goto (`wait_until="domcontentloaded"` + the
signal). Fixed waits that were removed: `wait_for_timeout(500)` and
`wait_for_timeout(150)`, and the animation settle is now two
`requestAnimationFrame`s, not a delay. The **only** `time.sleep` left in the file
is the 0.5 s interval of the bounded 120-attempt `/healthz` poll in
`start_server()` — a server-readiness retry, not a browser wait.

## 3. What is normalised, and the two surprises

Documented in the module docstring (and in the regenerated
`tests/golden/README.md`): `?v=<hash>` queries, Vite build hashes in dist
filenames, `data-ts`/`data-full`, relative ages (`just now`, `Ns/Nm/Nd ago`),
epoch/ISO timestamps, `/internal/metrics` values, sizes computed on normalised
bytes, and blobatar's random avatar phases.

Two things the first determinism run exposed that were not in the brief:

1. **`data-ts` never matched.** `home.html` renders
   `class="sync-line ..."data-ts="…"` with **no space** before `data-ts`, and the
   old regex required a leading whitespace. The sync epoch was in every recorded body and no
   capture could ever be byte-identical. The pattern no longer anchors on
   whitespace.
2. **blobatar randomises the avatar per request.** `--mo-phase`,
   `--mo-look-x`, `--mo-blink`, `--mo-saccade`, … arrive as inline CSS on the
   avatar `<svg>`, so the same student blinks differently on every page load.
   That moved DOM *and* pixels. Pinned at both ends: `normalize()` records `:0`
   and `_pin_mo_vars` serves documents with the same values pinned, so islands
   hydrate against what was recorded and the PNGs match.

Two more measured facts worth keeping:

* `page.clock.install(time=X)` on this playwright takes **seconds** (passing ms
  gives `Date.now()` ≈ 1.7e15) and the clock **keeps ticking** (+1204 ms over
  1.2 s). It is pinned to the injected blob's `ts`, which keeps every rendered
  age in the "just now" bucket with sub-second drift — that caption was the last
  differing glyph.
* Content-identical PNGs still differed by 1–5 px until chromium was launched
  with pinned rasterisation (`--force-color-profile=srgb`,
  `--force-device-scale-factor=1`, `--disable-lcd-text`,
  `--font-render-hinting=none`, `--disable-gpu`, `--disable-partial-raster`,
  `--disable-threaded-animation`, `--run-all-compositor-stages-before-draw`,
  `--hide-scrollbars`, `device_scale_factor=1`).

```

    --python /path/to/venv/bin/python \
    --out tests/golden/v2                            # v3 for the islands revision

```

Rules that still hold: playwright runs on the laptop via `lap` (L8/L9), never on
the lab; `scripts/capture_golden.py --selftest` asserts every normalisation rule
matches in ~50 ms and needs no browser — run it after touching `normalize()`.
