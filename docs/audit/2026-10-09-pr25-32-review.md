# 2026-10-09 — code review of PRs #25–#32: preserve-contract breaks, pole overlap, alert tripwire

**Symptom.** Merged PRs #25–#32 (attendance redesign, reliability, exams,
logging, feedback) shipped with degraded code quality: duplicated blocks
that drifted apart, tests green while features misrendered, and several
data-preservation contracts broken. A full review (four independent
review passes + two adversarial refutation passes; every P0/P1 claim
reproduced with its own probe before any fix) found no refuted P0/P1.

## Root causes and fixes

1. **Pole-band label collisions (attendance, up to 13.5px text-on-text).**
   The nudge ladder added fixed −10/−12px `nudP`/`nud2P` steps guarded only
   by `fill < 99.5`, which cannot pay for label width near the pole:
   119/120 overlapped 13.50px, 118/120 10.63px, 99/100 10.15px (measured
   at 393 and 1280). The DUT seeded only up to 45/46 and checked one
   viewport, so it certified the broken state.
   **Fix:** in the pole band (`dpol < 9`) render ONE right-anchored
   `attended / total` cluster (`pn-tot` carries both) and drop `pn-now` +
   nudges; DESIGN §4.15 pole rule rewritten. DUT seeds boundary fills
   (118/120, 99/100, 54/55, 43/45), scans overlaps at 393 **and** 320, and
   was red-tested (template revert → 3 failures printed).
   **Evidence:** before 3 overlap pairs @393 (max 10.6px) + fake-5-row
   collisions visible at 1280; after 0 @393, 0 @1280. Shots:
   `docs/screenshots/review-pr25-32/`.

2. **Exam schedule wiped by its own fallback (silent data loss).**
   `_merge_exam_results` returns `None` to mean "preserve stored", but the
   Playwright path passed it through unconditionally →
   `json.dumps(None)` = `"null"` stored, reloaded as `[]`; and an official
   parse drift returned `None` *before* the scribe fallback ran, freezing
   the schedule — with `test_exams.py` asserting the freeze as intended.
   **Fix:** omit the `exams` fetch key when the merge produced nothing (the
   `if "exams" in res` preserve contract now holds on every path); drift
   falls through to scribe rows; the enshrining assertion flipped.

3. **Preserve-if-empty contract duplicated, then drifted (login vs refresh).**
   Two hand-copies of the merge; refresh wrote `subjects_json`
   unconditionally where login preserved it — the exact marks-page failure
   that preserved marks would have wiped stored subjects on a hot refresh.
   **Fix:** one `_merge_fetch_result()` for both routes.

4. **Faculty map could be emptied by a failed harvest.** An all-teacherless
   harvest (every staff "Unknown") overwrote a good stored map, contradicting
   the README's "only overwritten by a fresh successful harvest".
   **Fix:** teacherless harvest returns `None` → key omitted → stored map
   kept. Feedback question ids are now parsed from the live form instead of
   hardcoded `range(23, 37)` (a portal-side renumber would have silently
   posted to the wrong questions).

5. **Alert tripwire fired on routine 4xx and stalled the logging path.**
   The ntfy handler accepted WARNING records (a 401 paged), the 500 alert
   said where but never what, `emit()` did a 5s POST while holding the
   handler lock (gunicorn threads share it), and a failed send consumed the
   next 60s window.
   **Fix:** emit gates on ERROR/`status>=500`; `error=%r` rides the
   unhandled-error line (so the alert carries the cause); POST moved to a
   daemon thread with a 10s re-arm on failure; telemetry failure log raised
   DEBUG → WARNING (dropped entirely at prod INFO before).

6. **500 responses handed browsers raw JSON** (`_unhandled_error` returned
   the API shape unconditionally). HTML navigations now get a minimal HTML
   500; fetch callers keep the JSON contract.

7. **Rendering defects:** fallback months (daily rows with no cumulative
   row) rendered a fake red 0% bar and promoted junk keys to months →
   now `pct=None` chip-only blocks (DESIGN §4.15); the Estimates card
   rendered header-only for timetable-less students → whole card gated on
   budgets; `faculty_map_json` decoded with hand-rolled `json.loads`
   (wrong shape = 500) → `_jload` on both sites.

8. **Dead weight removed:** `photo` result keys (no reader since Sep 25),
   `_fb_submit_comments`, `_fmt_period`, orphaned `.ql*`/`tt-sig svg` CSS,
   `tt-hero-dot`/`tt-hero--off` markup, sig `icon` keys, dead render kwargs,
   cold-sync JSPS `1` + `32` fetches (nothing read either — the harvester
   posts iden=32 itself), phantom `version=5` migration example, RUF021
   unparenthesised `or/and` predicate, a second copy of the 75/65 thresholds
   retyped in Jinja (`_BAND_BAR` on `_month_view`), `index()`'s three
   queries for one row, the personal-decode triplicate (`_load_personal`).

## Standing rules

- **A preserve contract is keyed on key PRESENCE, never on the value's
  truthiness at the write site** — every consumer of `fetch()` results must
  route through one merge helper; adding a column means adding it there.
- **A DUT that certifies a visual fix must seed the boundary class it
  claims to cover** (fills that land inside the collision band) and scan
  every viewport the layout supports; a green run that cannot enter the
  broken state proves nothing (red-test required).

## Deliberately left unfixed

- The two live fetch pipelines (`_fetch_rich_optimized` 206 LOC vs
  `http_scraper.fetch`) remain duplicated — merging them is a project, not
  a review fix; historical double-fix evidence is in the audit trail.
- Subject-level "already registered" probe can under-fill multi-teacher
  subjects — mechanism confirmed, needs a live 2-teacher portal test.
- `usage_events` still has no reader (write-only telemetry); README now
  claims only what exists.
- Request-id correlation promised in the 2026-10-07 audit is not in this
  PR; `error=<text>` kv formatting intentionally left unquoted (prod grep
  recipes + tests assert the exact shape).
- `/api/marks` keeps its zero-caller status (tested endpoint, removal is a
  product decision); `photo_b64` schema column kept (drop = migration risk
  for zero bytes).
